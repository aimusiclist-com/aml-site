# 이미 설치한 개인사이트 업데이트하기 (3-10 기준)

Deploy 버튼(또는 GitHub 연결)로 설치한 사이트는 **내 GitHub 저장소**가 원본입니다. 저장소에 새 파일이 들어가면 Cloudflare(Workers Builds)가 1~3분 안에 자동으로 다시 배포합니다.
곡·앨범·설정은 **R2(aml-music)** 에 있으므로 코드를 바꿔도 지워지지 않습니다.

방법은 두 가지입니다.

| 방법 | 언제 | 준비물 |
|---|---|---|
| **A. 버튼 한 번 (업데이트 받기)** | 3-8을 한 번 올린 뒤부터 | 없음 (GitHub 화면만) |
| **B. zip 풀어 올리기** | 처음 3-8로 올릴 때, 또는 A가 멈췄을 때 | 받은 zip 파일 |

> 3-7 이하에서 3-8로 갈 때는 **B를 한 번** 해야 합니다(그 전 버전에는 A 버튼이 없습니다). 그다음부터는 A로 됩니다.

---

## A. 버튼 한 번으로 업데이트 받기 (3-8부터)

관리 화면 맨 위에 **"새 버전이 있습니다 — 업데이트 방법"** 한 줄이 보이면 업데이트할 때입니다(강제는 아닙니다). 줄이 **빨간색 "꼭 업데이트하세요"** 로 보이면 aimusiclist.com이 지원하는 최소 버전보다 낮다는 뜻이니 되도록 빨리 업데이트하세요(그래도 사이트는 멈추지 않습니다). **바뀐 점** 링크가 있으면 무엇이 달라졌는지 볼 수 있습니다.

1. GitHub에서 내 저장소(예: `rbkkim`)를 엽니다.
2. 위쪽 메뉴에서 **Actions** 탭을 누릅니다.
   - 처음이면 초록 버튼 **I understand my workflows, go ahead and enable them** 이 나올 수 있습니다 → 누릅니다.
3. 왼쪽 목록에서 **Update from template (업데이트 받기)** 를 누릅니다.
4. 오른쪽의 **Run workflow** 버튼 → 작은 창이 열리면 아무것도 바꾸지 말고 아래 초록 **Run workflow** 를 누릅니다.
5. 1분쯤 뒤 목록에 생긴 줄이 **초록 체크(✓)** 가 되면 끝입니다. 그 줄을 누르면 **Summary**에 무엇이 바뀌었는지 나옵니다.
6. 1~3분 뒤 Cloudflare 대시보드 → **Workers & Pages** → 내 Worker → **Deployments** 에 새 배포가 성공(초록)으로 보이면 사이트도 바뀐 것입니다.

**이 버튼이 지키는 것** (아티스트가 올린 스킨·곡·사이트 설정·메뉴는 Cloudflare R2 에 있어서 코드 업데이트와 상관없이 그대로입니다. 3-8 시험에서 확인)
- `wrangler.toml` 의 **Worker 이름**(`name`), **R2 버킷 이름**(`bucket_name`), 내가 `[vars]`에 넣은 값, `account_id` — 그대로 둡니다. 그래서 설치 때 이름을 바꾼 사이트도 그대로 배포됩니다.
- `package.json` 맨 위 `name` — 그대로.
- (3.14) `wrangler.toml` 의 통계 칸(`[[analytics_engine_datasets]]`)은 3.14 이상에서 **내가 켰을 때만** 그대로 둡니다(3.12·3.13 이 자동으로 넣었던 칸은 꺼짐으로 바뀜 — 아래 2-W).
- `.github/aml-keep.txt` 에 적은 파일(한 줄에 하나, 예: `README.md`) — 건드리지 않습니다. 이 파일은 내가 만들면 됩니다(없어도 됩니다).
- Cloudflare 토큰은 쓰지 않습니다. 이 버튼은 내 GitHub 저장소에 커밋만 하고, 배포는 Cloudflare가 평소처럼 합니다.

**빨간 ✗ 로 멈췄을 때** — 아무것도 바뀌지 않았습니다. 줄을 눌러 **Summary**의 이유를 봅니다.

| Summary 문장 | 뜻 | 할 일 |
|---|---|---|
| `Conflict. / 충돌.` + 파일 목록 | 내가 직접 고친 프로그램 파일을 새 버전도 바꿨습니다 | 내 것을 지키려면 그 파일 이름을 `.github/aml-keep.txt` 에 적고(**Add file → Create new file**) 다시 Run workflow. 새 것으로 덮으려면 Run workflow 창에서 **force** 를 체크하고 실행 |
| `The template address is not set yet` | 업데이트 받을 주소가 아직 없습니다 | B(zip) 방법을 쓰거나, Run workflow 창의 **template** 칸에 안내받은 주소(예: `aimusiclist/aml-personal-site`)를 넣고 실행 |
| `Could not find the original of my version` | 내 버전의 원본을 찾지 못해 내가 고친 파일을 확인할 수 없습니다 | **force** 를 체크하고 실행(Worker 이름·버킷·keep 파일은 그대로 지켜집니다) 또는 B |
| `did not pass the check` | 받은 새 파일이 검사(문법·언어팩)를 통과하지 못했습니다 | 기다렸다가 다시 하거나 aimusiclist.com 에 알려 주세요 |
| `routes or environments` | `wrangler.toml` 에 직접 넣은 routes·env 설정이 있습니다 | `wrangler.toml` 을 `.github/aml-keep.txt` 에 적고 다시 실행(그 파일은 직접 관리) |
| 초록인데 `Only the file(s) below must be changed by hand` 안내 | 사이트는 업데이트됐지만 GitHub 규칙상 이 버튼은 `.github/workflows/` 파일을 바꿀 수 없습니다(이 파일은 거의 바뀌지 않습니다) | Summary 에 적힌 순서대로: ① "새 내용" 칸의 복사 버튼(□) ② 내 저장소에서 그 파일 열기 ③ 연필 아이콘(**Edit this file**) ④ Ctrl+A → Ctrl+V ⑤ **Commit changes...** → **Commit changes**. 급하지 않음 |
| `Permission denied` / `403` (push 단계) | 저장소가 쓰기를 막고 있습니다 | 저장소 **Settings → Actions → General → Workflow permissions** 에서 **Read and write permissions** 를 고르고 **Save** → 다시 실행 |

- 특정 버전으로 가려면 Run workflow 창의 **version** 칸에 `v3.8.1` 처럼 적습니다(비우면 최신).
- 이 버튼은 GitHub Actions 무료 시간(비공개 저장소 월 2,000분)을 한 번에 1분 정도 씁니다.

## B. zip 풀어 올리기 (GitHub 웹 화면, 프로그램 설치 없음)

1. 받은 zip(예: `3-8_개인사이트확장항목.zip`)을 컴퓨터에서 압축을 풉니다. (Windows: 오른쪽 클릭 → **압축 풀기**)
2. GitHub에서 내 저장소(예: `rbkkim`)를 엽니다.
3. **Add file → Upload files**를 누릅니다.
4. 압축을 푼 폴더 **안의 내용 전체**(`src`, `public`, `docs`, `tools`, `dev`, `.github`, `wrangler.toml`, `package.json` …)를 끌어다 놓습니다. 같은 이름 파일은 새 것으로 바뀝니다.
   - `.github` 처럼 점(.)으로 시작하는 폴더는 컴퓨터에서 숨겨져 보일 수 있습니다. Windows 탐색기 **보기 → 숨긴 항목**, Mac Finder **Cmd+Shift+.** 으로 보이게 한 뒤 함께 끌어다 놓습니다.
5. 맨 아래 **Commit changes**를 누릅니다.
6. Cloudflare 대시보드 → Workers & Pages → 내 Worker(사이트 주소 `이름.계정.workers.dev`의 `이름`, 기본 `aml-site`) → **Deployments**에서 새 배포가 성공(초록)인지 확인합니다(1~3분).

> 3-5 ~ 3-10 업데이트는 **지워야 하는 파일이 없습니다**(새 파일만 늘어남: 3-6은 `src/guestbook.js`, `src/domain.js` / 3-7은 `src/lists.js`, `public/_app/song-langs.json`, `public/_app/socials.json`, `public/_app/socials.svg`, `tools/socials-sprite.js` / 3-8은 `src/fields.js`, `tools/update-from-template.js`, `.github/workflows/update.yml`, `.github/aml-update.json` / 3-9는 `public/_app/base.css`, `kit.css`, `icons.svg`, `public/_app/fonts/`(글꼴 94개), `public/favicon.ico`, `tools/contrast-check.js`, `docs/아이콘_글꼴_라이선스.md` / 3-10은 `src/gallery.js`, `public/_app/preview.js`, `public/_app/lang-admin/`(3개), `dev/gallery/`). 그래서 4번처럼 올리기만 하면 됩니다.
> Worker 이름은 `wrangler.toml`의 `name`과 Cloudflare의 Worker 이름이 같아야 빌드가 됩니다. zip의 `wrangler.toml`은 기본 이름 `aml-site`입니다. **설치 때 Worker 이름을 바꿨다면**, 올리기 전에 압축을 푼 `wrangler.toml` 3번째 줄 `name = "…"`을 내 Worker 이름으로 고치거나 `wrangler.toml`만 빼고 올리세요. (A 방법은 이것을 자동으로 지킵니다.)

## 3-10 업데이트 (스킨 둘러보기·미리보기·한 번에 적용)
- 지워야 하는 파일 없음. R2 데이터 그대로, 방문자 화면 그대로(3-9 → 3-10 로컬 시험: 사이트·곡·앨범·메뉴·스킨 목록 같음, 방문자 page.html 바이트까지 같음).
- `wrangler.toml` 의 `[vars]` 에 `SKIN_INDEX_URL` 한 줄이 새로 있습니다. 내 `wrangler.toml` 을 그대로 두어도 됩니다(값이 없으면 `https://meshmelo.com/skins/index.json` 을 씀).
- 업데이트 뒤: 관리 화면 → 스킨 → **둘러보기**. meshmelo.com 에 스킨 목록(`/skins/index.json`)이 아직 올라가지 않았으면 "지금 스킨 목록을 불러올 수 없어요"가 보입니다(정상, 직접 올리기는 그대로 됨).

## 3-9 업데이트 (기본 디자인·새 재생 바·프로필 자르기)

- 지워야 하는 파일 없음. R2 데이터(곡·앨범·사이트 정보·메뉴·올린 스킨·방명록)는 그대로입니다(3-8 → 3-9 로컬 시험: 사이트·곡·앨범·메뉴·스킨 목록·catalog·방명록 모두 같음).
- **`light`·`dark` 를 쓰던 사이트만** 새 모양이 됩니다. 직접 올린 스킨을 쓰던 사이트는 그 스킨 그대로이고, 재생 바·비주얼라이저·곡 줄 버튼만 새것으로 바뀝니다.
- catalog 는 바뀌지 않습니다(우리사이트가 할 일 없음). 프로필 평균 색은 관리 화면을 한 번 열면 자동으로 저장됩니다.
- 처음 3-9로 올릴 때 GitHub 저장소 파일 수가 글꼴 때문에 94개 늘어납니다(전부 합쳐 약 3MB). **GitHub 웹 화면은 한 번에 100개까지만 올라가므로 두 번에 나눕니다**: ① `public/_app/fonts` 폴더를 뺀 나머지 전체 → Commit ② 저장소에서 `public/_app` 폴더로 들어가 **Add file → Upload files** → `fonts` 폴더째 → Commit.
- `wrangler.toml` 의 Worker 이름(`name`)과 R2 버킷 이름(`bucket_name`, 기본 `aml-music`)이 내 설치와 다르면 그 두 줄을 내 값으로 고친 뒤 올립니다(버킷 이름이 다르면 다른 버킷을 보게 되어 곡이 안 보입니다).

## 3-8 업데이트 (추가 정보·새 버전 안내·업데이트 받기) — 순서 주의

**우리사이트(aimusiclist.com)가 catalog 1.3을 받게 된 뒤(채팅 2-9 실서버 업데이트 뒤)에 올립니다.** 3-7을 아직 올리지 않았다면 3-7과 3-8을 이 zip 하나로 한 번에 올리면 됩니다(3-8 zip = 3-7 합본 + 3-8).

올린 뒤:
- 관리 화면을 열면 사이트가 aimusiclist.com에서 **추가 항목 목록(fields.json)** 을 받아 옵니다. 그 뒤로는 하루 1번 스스로 확인합니다(사이트마다 다른 시각).
- 곡 탭 업로드·곡 수정 화면의 장르·곡 언어·아티스트 아래에 **"추가 정보"** 칸(예: 분위기 Mood)이 생깁니다. 모두 선택 사항입니다. aimusiclist.com에 아직 항목이 없으면 이 칸은 보이지 않고, 곡 올리기는 평소처럼 됩니다.
- 곡 목록에서 여러 곡을 체크하면 위 칸에 **"선택한 곡의 추가 정보"** 가 생깁니다(하나 고르기·여러 개 고르기 항목).
- **사이트 정보** 탭: 사이트 단위 추가 정보(있을 때) + **추가 항목** 카드의 **Update fields** 버튼(바로 다시 받기, 1분에 1번).
- 방문자 화면 곡 줄의 장르 칩 옆에 작은 칩(예: `Calm`)이 보입니다(값을 넣은 곡만). 직접 만든 스킨도 그대로 동작합니다.
- R2 데이터는 그대로입니다. 처음 무엇인가 바꿀 때 catalog가 1.3으로 다시 만들어집니다(곡 내용은 같고 버전 표시만 바뀜).

## 3-7 업데이트 (곡 언어·SNS·사용량 토큰)

**우리사이트(aimusiclist.com)가 새 catalog를 받게 된 뒤(채팅 2-9 실서버 업데이트 뒤)에 올립니다.** 먼저 올리면 우리사이트가 새 목록을 거부하고 이전 목록을 그대로 둡니다(곡이 사라지지는 않지만 새 곡·변경이 반영되지 않음).

올린 뒤:
- 관리 화면 맨 위에 **"곡 언어를 확인해 주세요(n곡)"** 한 줄이 나옵니다 → **지금 지정** → 곡이 모두 체크된 채 목록이 열립니다 → 곡 언어 고르기 → **적용**. 미루어도 됩니다(그동안 우리사이트는 사이트 기본 언어로 봅니다).
- **사이트 정보** 탭 → **SNS**: 큰 5개 칸에 주소만, 다른 SNS는 "+ 다른 SNS 추가". 칸을 벗어나면 바로 저장됩니다.
- 방문자 화면 메뉴에 **링크**(Links)가 생깁니다(SNS를 넣었을 때만). 기본 스킨(light·dark)은 사이트 이름 아래에 SNS 아이콘 줄도 보입니다. 직접 만든 스킨은 `{{socials}}`를 넣어야 아이콘 줄이 보입니다(넣지 않아도 링크 화면은 동작).
- 사용량 막대가 "계정을 볼 수 없음"으로 실패하던 사이트는: 사이트 정보 → 관리자 계정 → 새 사용량 토큰(버튼으로 다시 만들면 권한 2줄이 채워짐) 또는 계정 ID 칸에 Account ID를 넣고 저장.
- R2 데이터는 그대로입니다. 곡에 언어 값이 없는 동안 catalog는 이전 그대로이고, 처음 무엇인가 바꿀 때 catalog 1.2로 다시 만들어집니다.

## 3-6 업데이트 뒤 확인 (모든 사이트)

**할 일 없음.** 곡·앨범·메뉴·스킨·관리자 계정·aimusiclist 연결은 그대로입니다. 새 설정은 모두 "켜면 생기는" 것이라 지금 화면은 거의 같고, 아래만 달라집니다.
- 곡 목록 재생 버튼 뒤에 곡 이미지(업로드 때 정해진 기본 이미지)가 보입니다. 메뉴에 **방명록**이 생깁니다(관리 화면 "방명록" 탭에서 끌 수 있음).
- 맨 아래 문구가 `© 올해 사이트이름` + ⚙ 관리로 바뀝니다. 직접 만든 스킨에 `© {{year}} …`를 써 두었다면 두 번 보이므로 그 줄을 `{{footer}}`로 바꾸세요.
- 관리 화면 새 탭: **방명록**, **내 도메인**. "사이트 정보" 탭에 하단 문구·배너·프로필·구글 애드센스. 곡 "수정"에 곡 이미지·가사(.srt). 앨범 커버는 200×200 자르기 도구로 올립니다(예전 JPG 커버는 그대로 보임).
- 확인 방법: 업데이트 1~3분 뒤 내 주소를 열어 곡이 재생되고 맨 아래 문구가 보이면 끝. aimusiclist.com 쪽은 바뀌는 것이 없습니다(catalog 내용이 같으면 다시 알리지도 않음).
