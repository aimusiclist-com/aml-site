## 1. 방식 (한 줄 요약)

**스킨 = HTML 파일 1개(`<style>` 포함). 업로드하면 Worker가 자리표시에 내용을 채워 바로 적용한다.**

- 곡 목록·메뉴·재생 바는 사이트가 공통 스크립트(`/_app/visitor.js`)로 그린다. 스킨은 **자리와 색(CSS)만** 정한다.
- 사이트는 스킨의 `<style>` **앞에** 기본 모양 파일을 넣는다: `/_app/base.css`(재생 바·비주얼라이저·버튼·가사 창 — 모든 스킨), `/_app/kit.css`(기본 디자인 — `{{hero}}` 나 `class="aml-kit"` 가 있는 스킨만). 스킨 CSS가 뒤에 오므로 무엇이든 덮어쓸 수 있다.
- 두 가지 만드는 법:
  - **A. 기본 디자인 + 내 색 (권장, 무료 AI로 5분)**: `<body class="aml-kit">` + 자리표시 배치 + `:root` 색 변수. 기본 스킨 `light`·`dark`가 이 방식이다(각 2~4KB).
  - **B. 처음부터 내 디자인**: `aml-kit` 없이 4장 클래스에 CSS를 직접 입힌다(v1.4까지의 방식). 재생 바는 그래도 사이트가 그린다.
- 기본 스킨: `light`(흰 바탕, 메뉴는 머리 영역 아래 알약 탭), `dark`(검정 바탕, 넓은 화면에서 왼쪽 반투명 사이드바). 파일 `public/_skins/`, 관리 화면 Skins 탭에서 내려받아 고쳐 쓸 수 있다.

## 2. 파일 규칙

| 항목 | 규칙 |
|---|---|
| 파일 | `.html` 1개, UTF-8 |
| 크기 | 100KB 이하 (A 방식은 보통 5KB 안팎) |
| 이름 | 영문 소문자·숫자·`-`·`_`, 1~32자 (`light`, `dark`는 기본 스킨이라 사용 불가) |
| CSS | 반드시 `<style>` 안에. 외부 CSS 파일 불가 |
| 이미지 | 넣고 싶으면 `data:` 주소(작은 배경·무늬)만. 외부 이미지 주소 불가 |
| 글꼴 | 기기 글꼴(system-ui 등) 또는 **사이트 글꼴 `var(--aml-font)`**(Pretendard 포함). 외부 웹폰트 주소 불가 |
| 필수 | `{{menu}}`, `{{content}}`, `{{player}}` 를 **각각 정확히 1번** 넣는다 |
| 권장 | `<meta charset="utf-8">`, `<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">`, `<html lang="{{lang}}">`, `<meta name="theme-color" content="바탕색">` |
| 검색 태그 (3-27) | **head 에 엔진이 검색용 태그를 넣는다 — 스킨은 같은 태그를 넣지 말 것.** `<title>`(페이지마다 "곡 제목 — 아티스트 \| 사이트 이름"으로 바뀜)·`description`·`canonical`·`og:*`·`twitter:*`·`robots`·JSON-LD 는 엔진 몫이다. 스킨에 `<title>{{site_name}}</title>` 하나만 두면 된다. 스킨에 `<meta name="description">`·`og:`·`twitter:` 메타가 있으면 페이지에서는 빠지고 `node tools/skin-check.mjs` 가 WARN 으로 알려 준다 |
| 대비 | 본문 글자 4.5:1 이상. `node tools/contrast-check.js 내스킨.html` 로 확인(A 방식) |

- 글자 자리표시는 자동으로 안전하게 바뀐다(`<` 같은 문자가 그대로 보임). 목록에 없는 `{{…}}`는 지워진다.
- 자리표시 이름은 HTML 주석·CSS 주석 안에도 쓰지 않는다(주석 안에서도 바뀐다).
- `{{tracks}}`, `{{play_all}}` 같은 자리는 없다. 곡 목록은 화면에 따라 `{{content}}` 안에, 전체 재생 버튼은 `{{hero}}` 안에 그려진다.

### 4-2. 기본 디자인(A)의 배치 부품

## 5. 금지 사항 (업로드 때 검사해서 거부한다)

| 금지 | 이유 |
|---|---|
| `<script>`, `onclick=` 같은 `on…=` 속성, `javascript:` | 스크립트 실행 차단 |
| `<iframe>`, `<frame>`, `<object>`, `<embed>`, `<applet>` | 다른 페이지·플러그인 삽입 차단 |
| `<form>`, `<input>`, `<button>`, `<textarea>`, `<select>` | 가짜 입력창(비밀번호 가로채기 등) 차단 |
| `<link>`, `<base>`, `<meta http-equiv>` | 외부 파일 로드·주소 바꾸기 차단 (`<meta name="theme-color">` 등 name 메타는 허용) |
| CSS `@import`, `url(http…)`, `url(//…)`, `expression(` | 외부 파일 로드 차단 |
| `src=`·`srcset=`·`poster=`에 외부 주소 | 외부 파일 로드 차단 |
| 맨 아래 **Powered by aimusiclist.com** 줄을 숨기기·지우기 (3-19) — `{{footer}}` 를 주석·`<head>`·`<template>`·`<noscript>`·`<style>`·`<title>`·`hidden`/`display:none` 요소 안에 두기, `.aml-footer`·`.aml-adminbar`·`.aml-powered` 를 `display:none`·`visibility:hidden`·`opacity:0`·`font-size:0` 으로 만들기 | **필수**: 맨 아래 Powered by aimusiclist.com 표시는 이 소프트웨어 사용 조건입니다. 지우거나 숨기지 말아 주세요. (검사가 못 잡는 다른 방법 — 글자색을 바탕색과 같게, 화면 밖으로 밀기 등 — 도 금지) |

- 일반 링크 `<a href="https://…">`는 허용한다.
- 검사를 통과해도 방문자 페이지에는 보안 헤더(CSP)가 붙어서 사이트 스크립트(`/_app/*.js`) 말고는 실행되지 않는다.
- 거부되면 오류 코드: `err.skin.too_large`, `err.skin.placeholder`(자리표시 누락·중복), `err.skin.forbidden`(무엇이 금지인지 함께 표시), `err.skin.empty`.

## 6. 적용 방식 (참고)

1. 관리 화면(`/admin/` → Skins 탭)에서 이름을 정하고 스킨 파일을 올린다 → 검사 통과 시 R2 `skins/{이름}.html`. 같은 이름이면 덮어쓴다(최대 20개).
2. "Use this skin" → R2 `meta/ui.json`의 `skin`이 바뀌고 바로 적용된다.
3. Worker가 스킨 + 곡 목록 + 메뉴를 합쳐 완성된 페이지를 R2 `meta/page.html`에 만들어 둔다(방문 때마다 만들지 않는다). 방문자 화면에는 최대 30초 안에 반영.
4. 올린 스킨이 지워지면 자동으로 `light`로 돌아간다.
5. 사이트를 새 버전으로 업데이트해도 아티스트가 고른 스킨은 바뀌지 않는다. `light`·`dark`를 쓰던 사이트만 새 기본 모양이 된다.

## 8. 스킨 갤러리에 올리는 형식 (v1.5, 3-10 "스킨 둘러보기·설치"가 읽는다)

스킨 원본은 GitHub `aml-personal-site` 저장소의 `skins/{id}/` 폴더 하나 = 스킨 하나. (GPT·사람이 PR로 올리고, 조율 채팅이 검사·merge, 배포는 meshmelo.com/skins/index.json)

```
skins/{id}/
  skin.html      ← 이 규격의 스킨 파일 (A 방식 권장, 30KB 이하)
  meta.json      ← 아래 형식
  preview.webp   ← 미리보기 1200×750 (데스크톱 첫 화면), 100KB 이하
  preview-m.webp ← (선택) 휴대폰 미리보기 390×844 를 2배가 아닌 1배로, 60KB 이하
```

`meta.json`
```json
{
  "schema": "skin-1",
  "id": "cassette",
  "version": "1.0.0",
  "spec": "1.5",
  "name": { "en": "Cassette", "ko": "카세트", "ja": "カセット" },
  "description": { "en": "Warm cream paper with orange accents.", "ko": "따뜻한 크림색 종이와 주황 포인트.", "ja": "クリーム色の紙とオレンジのアクセント。" },
  "mode": "light",
  "tags": ["retro", "warm"],
  "author": "aimusiclist",
  "license": "CC0-1.0"
}
```
- `id`: 영문 소문자·숫자·`-`, 1~32자, 폴더 이름과 같게, `light`·`dark` 사용 불가. 설치하면 이 이름으로 저장된다.
- `version`: 고치면 올린다(`1.0.1`). 설치한 사이트에 "새 버전" 안내를 띄우는 기준(3-10).
- `spec`: 맞춘 스킨 규격 판. `mode`: `light` | `dark`. `tags`: 영문 소문자 0~5개. `name`·`description`: en 필수, ko·ja 권장(각 40자·120자 이하).
- 올리기 전 확인: ① 5장 금지 사항 없음(사이트 업로드 검사와 같은 규칙) ② `node tools/contrast-check.js skins/{id}/skin.html` 통과 ③ 30곡·1곡·0곡, 프로필 있음/없음, 배너 있음/없음, 휴대폰 390에서 깨지지 않음.

### 8-1. 설치될 때 무엇을 검사하나 (3-10)
아티스트가 관리 화면 **스킨 → 둘러보기**에서 [적용]·[업데이트]·[미리보기]를 누르면 사이트 서버가 meshmelo 목록(`index.json`)을 다시 받아 그 `id`의 `html` 주소를 찾고, ① 주소가 목록과 같은 호스트인지(다른 곳·리다이렉트는 거부) ② 100KB·5초 안에 받아지는지 ③ 받은 파일의 sha256이 목록의 `sha256`과 같은지 ④ `spec`이 그 사이트가 아는 판 이하인지 ⑤ 5장 금지 사항·필수 자리표시(직접 올릴 때와 같은 `checkSkin()`)를 확인한다. 하나라도 틀리면 설치하지 않고 이유만 보여 준다. 그러니 스킨을 고치면 `version`을 올리고 목록을 다시 만들어(sha256 갱신) 올려야 한다 — 그래야 설치한 사이트에 "새 버전"이 뜨고 [업데이트]가 통과한다. `spec`을 1.6처럼 올린 스킨은 아직 1.5까지만 아는 사이트에서 "사이트를 업데이트하면 쓸 수 있어요"로 보이고 설치되지 않는다.
