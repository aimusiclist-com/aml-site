# 언어팩 제작 매뉴얼 — 개인사이트

기준: 채팅 3-3. 이 문서만 보고 사람이나 무료 AI(ChatGPT·Claude 무료 버전)가 새 언어를 추가할 수 있어야 한다.

---

## 1. 한눈에 보기

| 무엇 | 어디 |
|---|---|
| 영어 원본 문장 (기준) | `public/_app/strings.js` 안의 `AML.strings.en` |
| 언어 목록 (선택 목록에 나오는 언어) | `public/_app/strings.js` 맨 위 `AML.LANGS` **한 줄** |
| 언어팩 (언어 1개 = 파일 1개) | `public/_app/lang/{언어코드}.js` (예: `ko.js`, `ja.js`) |
| 검사 도구 | `tools/lang-check.js` |

- 방문자 화면과 관리 화면(/admin/)이 **같은 언어팩**을 쓴다.
- 방문자는 화면의 언어 선택 목록으로 언어를 바꾼다. 고른 언어는 그 브라우저에 저장되어 다음 방문에도 유지된다.
- 처음 방문하면 이 순서로 언어를 정한다: 저장한 언어 → 브라우저 언어 → 사이트 기본 언어(관리 화면 "사이트 정보") → 영어.
- 언어팩에 없는 문장은 **영어로** 보인다. 그래서 일부만 번역해도 화면이 깨지지 않는다.
- 방문자가 고른 언어 파일 1개만 불러온다. 정적 파일이라 무료이고 Worker·R2 요청이 늘지 않는다.

## 2. 새 언어 추가 순서 (예: 프랑스어 fr)

1. **언어 코드 정하기**: 영문 소문자 2글자(ISO 639-1). 지역을 나눌 때만 `-`를 붙인다.
   예) `fr` 프랑스어, `es` 스페인어, `de` 독일어, `vi` 베트남어, `zh-cn` 중국어 간체, `zh-tw` 중국어 번체, `pt-br` 브라질 포르투갈어
2. **빈 틀 만들기**: 개인사이트 폴더에서
   ```
   node tools/lang-check.js --template fr > public/_app/lang/fr.js
   ```
   → 영어 문장이 그대로 들어 있는 `fr.js`가 생긴다. (Node가 없으면 `lang/ko.js`를 복사해서 이름을 바꿔도 된다)
3. **번역하기**: 파일 내용을 무료 AI에 붙여넣고 번역을 시킨다(8장 요청문). 받은 결과로 `fr.js`를 덮어쓴다.
4. **목록에 한 줄 추가**: `public/_app/strings.js` 맨 위
   ```js
   AML.LANGS = { en: 'English', ko: '한국어', ja: '日本語', fr: 'Français' };
   ```
   이름은 **그 언어로 쓴 이름**(Français, Español, Deutsch …)으로 쓴다. 선택 목록에 이 이름이 그대로 나온다.
   ※ 새 언어 때문에 고치는 코드는 이 한 줄뿐이다.
5. **검사**: `node tools/lang-check.js fr` → "모두 정상입니다"가 나오면 끝.
6. **시험**: `npx wrangler dev` → `http://localhost:8787/` 에서 언어 선택 목록에 Français가 나오는지, 고르면 바뀌는지 확인.
7. **배포**: `npx wrangler deploy`

### 2-1. 관리 화면 전용 문장 (3-10~)
관리 화면에만 나오는 새 문장은 방문자가 받는 파일을 키우지 않도록 `public/_app/lang-admin/{코드}.js` 에 따로 둔다(영어 원본 = `lang-admin/en.js`, 형식은 `lang/` 과 같다). 새 언어를 넣을 때 `lang-admin/en.js` 를 복사해 `lang-admin/{코드}.js` 로 만들고 오른쪽 문장만 번역한다. `node tools/lang-check.js` 가 두 폴더를 모두 검사한다.

## 3. 파일 형식

```js
// 프랑스어 언어팩 (fr)
AML.addLang('fr', {
  "nav.home": "Accueil",
  "album.track_count.one": "{n} titre",
  "album.track_count.other": "{n} titres",
  "err.rate_limited": "Trop de requêtes. Réessayez dans {retry_after} secondes."
});
```

- 첫 줄 `AML.addLang('fr', {` 의 코드는 **파일 이름과 같아야** 한다.
- 한 줄에 `"키": "문장",` 하나. 마지막 줄 뒤에는 쉼표가 없어도, 있어도 된다.
- 파일은 UTF-8로 저장한다(메모장: "다른 이름으로 저장" → 인코딩 UTF-8).
- `//` 로 시작하는 줄은 메모(주석)라서 화면에 나오지 않는다.

## 4. 번역할 때 지킬 것

| 규칙 | 예 |
|---|---|
| **키(왼쪽)는 절대 바꾸지 않는다** | `"nav.home"` → 그대로 |
| **`{중괄호}` 안의 변수는 그대로 둔다** (번역 금지, 위치는 옮겨도 됨) | `{n}`, `{title}`, `{file}`, `{max_kb}`, `{retry_after}`, `{genre}`, `{name}`, `{code}`, `{field}`, `{what}`, `{max}`, `{i}` |
| 문장 안의 큰따옴표는 `\"` 로 쓴다 | `"Press \"Save changes\""` |
| 이름·기술 용어는 번역하지 않는다 | `aimusiclist.com`, `MP3`, `M4A`, `JPG`, `WebP`, `KB`, `MB`, `AML_ADMIN_TOKEN`, `AML_SITE_SECRET`, `AML_SITE_ID`, `https://`, `docs/스킨규격.md` |
| 버튼 이름은 짧게 | "Upload" → 한 단어 정도 |
| 다른 문장에서 버튼 이름을 말할 때는 그 버튼 번역과 똑같이 | `publish.needed`, `publish.help`, `menu.help` 안의 "Save changes" = `publish.button` 의 번역 |
| `.one` / `.other` 는 단수·복수 | 1개일 때 `.one`, 나머지 `.other` |

**단수·복수**
- 한국어·일본어·중국어처럼 구분이 없는 언어: `.other` 줄만 있으면 된다(`.one` 줄은 지워도 된다).
- 러시아어·아랍어처럼 형태가 더 많은 언어: `.few`, `.many`, `.two`, `.zero` 를 추가할 수 있다. 브라우저의 언어 규칙(Intl.PluralRules)으로 자동 선택하고, 없으면 `.other`를 쓴다.
  예) `"album.track_count.few": "{n} трека"`

**장르 이름은 언어팩에 없다**
- 장르 이름(R&B, 힙합 …)은 우리사이트(aimusiclist.com)의 장르 목록(`genres.json`)에서 언어별로 가져온다. 새 언어의 장르 이름이 없으면 영어로 보인다.
- 장르 이름을 새 언어로 보이게 하려면 우리사이트 장르 목록에 그 언어 이름을 추가해야 한다(우리사이트 작업). 예비 목록은 `public/_app/genres-sample.json`.

**곡 언어·SNS 이름도 언어팩에 거의 없다 (3-7)**
- 곡 언어 목록(`public/_app/song-langs.json`)은 **그 언어로 쓴 이름**(English, 한국어, Español …)을 그대로 보여 주므로 번역하지 않는다. 언어팩에는 `songlang.zxx`(연주곡)·`songlang.mis`(기타 언어) 두 줄만 있다.
- (3-8) 확장 항목의 **이름**(예: Mood·분위기)과 옵션 이름은 언어팩이 아니라 aimusiclist.com 의 `fields.json` 에 언어별로 들어 있다(없는 언어는 영어). 언어팩에는 그 칸을 둘러싼 문장(`ext.*`, `fields.*`, `ver.*`, `bulk.ext*`, `err.fields.*`, `err.ext.*`)만 있다. `err.ext.*` 의 `{name}` 자리에는 항목 이름이 들어간다.
- (3-9) 새 문장 묶음: `hero.*`(머리 영역 곡 수·[전체 재생][섞어 재생]·소개 "더 보기"), `player.*`(재생 바·전체 화면 재생·음량·가사 버튼 — 화면 읽기 프로그램용 이름이 대부분), `track.more`·`track.play_next`·`track.gb_write`(곡 줄 ⋯ 메뉴), `home.see_all`, `crop.*`(관리 화면 프로필 자르기), `profile.note*`, `skin.installed`. 버튼 글자(`hero.play_all`, `hero.shuffle`)는 휴대폰에서 버튼 2개가 한 줄에 들어가야 하므로 **8글자(한글 기준 5글자) 안팎**으로 짧게.
- SNS 이름(YouTube, Instagram …)은 브랜드 이름이라 번역하지 않는다. 언어팩에는 `social.kakao`(카카오톡 채널) 한 줄만 있다. 다른 SNS도 나라마다 부르는 이름이 다르면 `social.{키}` 줄을 추가하면 그 이름이 쓰인다.
- 곡 언어나 SNS 종류를 늘리는 것은 언어팩이 아니라 그 JSON 파일에 한 줄 추가하는 일이다.

## 5. 번역이 빠졌는지 확인하는 방법

**방법 1: 검사 도구 (권장)** — 개인사이트 폴더에서

```
node tools/lang-check.js          # 모든 언어
node tools/lang-check.js fr       # fr만
```

결과 읽는 법:

| 표시 | 뜻 | 고치는 법 |
|---|---|---|
| `번역 390/390 (100%) ✓` (3-6 기준 문장 수) | 정상 | — |
| `✗ 빠진 키` | 그 문장은 영어로 보인다 | 영어 문장을 참고해 한 줄 추가 |
| `✗ 모르는 키` | 키 이름이 바뀌었다(오타) | 영어 원본과 같은 키로 고치기 |
| `✗ 변수 다름` | `{n}` 같은 변수가 빠졌거나 번역됨 | 영어와 같은 변수로 고치기 |
| `✗ 문법 오류 … N번째 줄` | 따옴표·쉼표가 빠짐. 파일 전체가 안 읽혀 영어로 보인다 | 그 줄 근처의 `"` `,` 확인 |
| `✗ AML.LANGS 에 없습니다` | 파일은 있지만 선택 목록에 안 나옴 | 2장 4번의 한 줄 추가 |
| `⚠ 영어와 같은 문장` | 오류는 아님. 번역을 잊었을 수 있음 | 필요하면 번역 |

**방법 2: 브라우저에서** — 사이트를 그 언어로 바꾼 뒤 F12 → Console 탭에 입력

```js
AML.missingKeys('fr')
```

빈 목록 `[]`이 나오면 빠진 것이 없다.

## 6. 이미 있는 언어팩을 고쳤을 때

- 파일을 고친 뒤 `strings.js` 의 `AML.V = '3'` 숫자를 하나 올리면(예: `'4'`) 방문자 브라우저가 옛 파일 대신 새 파일을 받는다.
- 영어 원본(`strings.js`)에 새 문장(키)이 추가되면, 각 언어팩에도 추가해야 한다. `node tools/lang-check.js` 로 빠진 키를 찾을 수 있다. (추가 전까지는 그 문장만 영어로 보인다)

## 7. 하지 말 것

- `strings.js` 의 영어 키 이름을 바꾸지 않는다(모든 언어팩이 깨진다).
- 언어팩 파일에 문장 말고 다른 코드를 넣지 않는다. 언어팩은 관리 화면에서도 실행되는 파일이다. **남이 준 언어팩 파일은 내용을 열어 보고**, `AML.addLang(` 과 `"키": "문장"` 줄만 있는지 확인한 뒤 넣는다.

## 8. 무료 AI에게 붙여넣을 요청문 예시

아래를 통째로 복사해 무료 ChatGPT나 Claude에 붙여넣는다. 첫 두 줄의 언어만 바꾸고, 맨 아래 `[여기에 파일 내용]` 자리에 2장 2번에서 만든 파일(또는 `lang/ko.js`) 내용을 붙여넣는다.
결과가 길어서 중간에 끊기면 "이어서"라고 입력하고, 받은 조각을 순서대로 이어 붙인다. 너무 길면 파일을 반으로 나눠 두 번에 번역시켜도 된다(나눌 때는 `AML.addLang(` 첫 줄과 `});` 끝 줄을 각각 붙여 보낸다).

```text
[번역할 언어: 프랑스어 (fr)]
[선택 목록에 보일 언어 이름: Français]

아래는 음악 사이트(아티스트 개인 사이트와 그 관리 화면)의 "언어팩" 파일이다.
이 파일을 위 언어로 번역해서, 같은 형식의 파일 전체를 코드 블록 하나로 돌려줘.

[규칙]
1. 첫 줄 AML.addLang('xx', { 의 'xx' 를 위 언어 코드로 바꾼다. 맨 끝 }); 은 그대로 둔다.
2. 각 줄은 "키": "문장", 형식이다. 왼쪽 키는 절대 바꾸지 말고, 오른쪽 문장만 번역한다.
3. {n} {title} {file} {max_kb} {retry_after} {genre} {name} {code} {field} {what} {max} {i} 처럼
   중괄호로 감싼 부분은 번역하지 말고 글자 그대로 둔다. 문장 안에서 위치만 자연스럽게 옮긴다.
4. 문장 안의 큰따옴표는 \" 로 쓴다. 문장을 감싸는 따옴표는 큰따옴표(")만 쓴다.
5. 다음은 번역하지 않는다: aimusiclist.com, MP3, M4A, JPG, WebP, KB, MB, AML_ADMIN_TOKEN, AML_SITE_SECRET,
   AML_SITE_ID, https://, docs/스킨규격.md
6. 버튼 이름(…button, …save, …delete, …edit, …cancel 등)은 짧게. 다른 문장 안에서 "Save changes" 버튼을
   말할 때는 "publish.button" 의 번역과 똑같은 말을 쓴다.
7. 키 끝이 .one 은 1개일 때, .other 는 여러 개일 때 문장이다. 이 언어에 단수/복수 구분이 없으면 .one 줄은 지운다.
   러시아어처럼 형태가 더 있으면 .few / .many 줄을 추가해도 된다.
8. 말투: 웹사이트 화면에 맞는 짧고 정중한 말투. 사용자는 음악을 올리는 아티스트와 음악을 듣는 방문자다.
9. // 로 시작하는 메모 줄은 그 언어로 번역해도 되고 지워도 된다.
10. 줄을 빠뜨리거나 합치지 말고, 원본과 같은 순서로 모든 줄을 번역한다. 설명은 쓰지 말고 파일 내용만 준다.

[여기에 파일 내용]
```

받은 뒤에는 2장 4~6번(목록 한 줄 추가 → 검사 → 시험)을 한다.
